# LogLeopard web

React client for the local LogLeopard service.

## Development

```sh
pnpm install --frozen-lockfile
pnpm run generate:api
pnpm run dev
```

Append `?mock=1` or set `VITE_MOCK_API=true` to use synthetic fixtures without a backend. Mock queries containing `mock:error` exercise the error state and `mock:expired` exercises session expiry.

## Checks

```sh
pnpm run lint
pnpm run typecheck
pnpm run check:api
pnpm run test
pnpm run build
pnpm exec playwright install chromium
pnpm run test:e2e
```

The client stores display/query preferences and at most 50 query-history strings in local storage on a best-effort basis; unavailable or quota-limited browser storage does not interrupt the UI. Query drafts remain persisted for session restoration when history or local recipe storage is disabled; those toggles control only automatic history and named recipes. Query results are memory-only. Pairing accepts `#pair=<token>`, posts the token to the local service, then removes the fragment.

## API boundary

Run `make openapi` from the repository root, then `pnpm run generate:api` from `web/` when the Go API changes. `src/api/schema.d.ts` is generated by the pinned `openapi-typescript` version and must not be edited manually. `pnpm run check:api` fails when it differs from `../openapi.json`.

Backend DTO aliases are derived from the generated schema in `src/api/types.ts`; the handwritten `ApiClient` is the narrow UI seam. Source discovery also preserves the backend's `X-LogLeopard-Warning` response header so successful fallback discovery remains distinct from a failed request. Requests use same-origin `/api/v1`, JSON, and `credentials: include`.
